## Keputusan desain

- **Satu validator, dimuat dari isi folder `schemas/`.** Skema baru otomatis ikut; tidak ada daftar yang harus diingat untuk diperbarui. Plugin bisa meng-import modul yang sama (Node murni, tanpa bundler).
- **`strict: true`.** Kata kunci salah ketik atau konstruksi ambigu ditolak saat skema dimuat, bukan diam-diam diabaikan. Mode ini langsung menangkap dua kelemahan di skema saya sendiri:
  1. `approval-record`: `minLength` pada `note` tanpa `type: string` (kini ditambah).
  2. `verification-result`: `required: ["reason"]` pada cabang `then` tanpa mendefinisikan propertinya (kini didefinisikan, dan sekaligus mewajibkan alasan tidak kosong / bukan spasi saja).
- **Test pelindung cakupan.** Test yang menggagalkan build bila ada skema baru di `schemas/` tanpa contoh valid dan minimal 2 kasus invalid.
- **`approval-record`: `decided_by` hanya boleh `owner`** (`const`). Skema sendiri tidak bisa mengungkapkan record "approved oleh agent". Penegakan sesungguhnya (token owner) ada di F2.1; skema adalah lapis kedua.

## Yang tidak bisa diverifikasi dan alasannya

- **Skema belum diuji terhadap data nyata.** Contoh valid dibuat tangan. Keluaran Researcher nyata dari F0.2 akan diuji di F1.2/F1.0c; sudah diketahui keluaran itu tidak memuat `id`, `generatedAt`, dan `windowDays` (lihat risiko).
- **Plugin belum meng-import validator.** Dipakai pertama kali di F1.0d/F1.3. Perlu dipastikan impor lintas folder (`plugins/` → `schemas/`) berjalan dalam proses worker Paperclip.

## Risiko atau asumsi baru

1. **Kontrak keluaran Researcher tidak cocok dengan `research-output.json`.** Keluaran nyata F0.2 hanya `{ "candidates": [ {title, summary, url, published_at, source_name} ] }`. Skema saya mewajibkan `id` per kandidat, `generatedAt`, `windowDays`. Rencana untuk F1.2: LLM hanya menghasilkan bentuk sederhana; **kode** menambahkan `id` (`c01`…), `generatedAt`, `windowDays` sebelum validasi. ID yang dibuat kode lebih tahan dibanding ID yang dikarang LLM, dan itu menjaga prinsip "LLM tidak memegang otoritas".
2. **`published_at` pada keluaran nyata bercampur format** (`2026-10-04` dan `2026-10-04T13:12:05Z`). Pola skema menerima keduanya.
3. **`schemas/validate.mjs` membaca semua `*.json` di folder `schemas/`.** Berkas JSON non-skema di folder itu akan ikut dimuat dan bisa merusak semua validasi. Aturan: folder itu hanya untuk skema.
