## Masalah nyata yang ditemukan dan diperbaiki

### PowerShell `Invoke-RestMethod` menggantung selamanya

Installer versi pertama ditulis dengan PowerShell dan **menggantung tanpa batas** saat membuat agent. Gejalanya menyesatkan: request bahkan tidak pernah muncul di log server, dan `-TimeoutSec` tidak pernah memicu.

Diagnosis dilakukan dengan bisect, bukan tebakan:

| Percobaan | Hasil |
| --- | --- |
| Payload minimal (`name` + `role`) | OK 0,3 s |
| + `title`, `icon`, `capabilities` | OK 0,2 s |
| + `instructionsBundle` kecil | OK 0,1 s |
| + `adapterType=codex_local` | OK 0,3 s |
| ASCII panjang (jsonLen 2827) | OK 0,2 s |
| Non-ASCII pendek (jsonLen 187) | OK 0,1 s |
| **File instruksi asli penuh (panjang + non-ASCII)** | **menggantung > 180 s** |
| Separuh pertama file | OK 0,2 s |
| Separuh kedua file | OK 0,1 s |

Kesimpulan: kombinasi **body panjang + karakter non-ASCII** (teks Indonesia dengan `≥`, `—`, `×`) membuat PowerShell 5.1 mengirim `Content-Length` yang tidak cocok dengan byte UTF-8 sebenarnya. Server menunggu sisa body yang tidak pernah datang.

Perbaikan: installer ditulis ulang di **Node** memakai `fetch` dengan `Buffer.byteLength` sehingga Content-Length benar. Setelah itu 5 agent terpasang dalam 0,9 detik. `scripts/install-division.ps1` dihapus agar tidak dipakai orang lain.

Catatan: saya sempat memperburuk keadaan dengan "perbaikan" memakai body `byte[]`, yang juga menggantung. Itu salah arah dan sudah dibuang.

### Sisa 8 agent probe

Proses bisect membuat 8 agent uji (`Probe*`) di EdukasiAI. Semuanya **sudah dihapus**; `agent list` sekarang tepat 5. Satu folder instruksi milik agent terhapus (`d54dd5c1-...`) masih tertinggal di data Paperclip — tidak mengganggu, tetapi menandakan Paperclip tidak membersihkan folder instruksi saat agent dihapus.

## Yang tidak bisa diverifikasi dan alasannya

- **AC0.3 (isolasi company)** — belum diuji. Butuh agent di `IsolationTest` beserta API key, lalu membuktikan ia tidak bisa membaca issue EdukasiAI. `IsolationTest` sengaja dibiarkan kosong karena itu pekerjaan F0.3 berikutnya.
- **AC0.2 (1 run agent, biaya USD 0)** — belum ada agent yang dijalankan sama sekali. Semua berstatus `idle`, `spentMonthlyCents=0`. Membuat agent **tidak** menimbulkan biaya; biaya baru muncul saat run.
- **Kualitas instruksi agent** — belum teruji perilaku. Baru terbukti tersimpan dengan benar, bukan bahwa agent mematuhinya.
- **Budget guard (AC0.5)** — `budgetMonthlyCents` per agent masih 0 (bawaan). Belum disetel maupun diuji.

## Risiko atau asumsi baru

1. **`codex_local` memakai kredensial Codex milik owner.** Ini satu-satunya adapter yang lolos, dan dipilih sebagai `defaultAdapterType` di manifest supaya agent bisa dijalankan. Konsekuensinya run akan memakai langganan Codex owner, bukan model gratis seperti rencana PRD. **Belum ada run, jadi belum ada biaya.** Owner perlu memutuskan sebelum F0.2 dijalankan. Mengubahnya cukup satu baris di `division.json` lalu jalankan ulang installer.
2. **Tiga adapter gratis pilihan PRD tidak tersedia.** `gemini`, `opencode`, dan `pi` butuh CLI yang belum terpasang. Memasangnya berarti instalasi perangkat lunak tambahan dan kemungkinan akun/API key. Ini mengubah asumsi biaya di PRD bagian 1.
3. **Dua agent memakai `role=qa`** (Verifier dan QA) karena enum role Paperclip tidak punya "verifier". Enum yang tersedia: ceo, cto, cmo, cfo, security, engineer, designer, pm, qa, devops, researcher, general. Tidak masalah secara fungsi, tetapi org chart akan terlihat punya dua QA.
4. **`Office Mega Class` masih ada** dan bukan dibuat oleh saya. Sekarang ada 3 company. Perlu keputusan owner: dipakai, dibiarkan, atau dihapus.
5. **Server bergantung pada shell yang hidup.** Sudah diperbaiki sebagian dengan `start-paperclip.ps1` yang menjalankan proses detached, sehingga tidak ikut mati saat sesi Claude Code berakhir. Tetap tidak auto-start setelah reboot.
6. **Repo masih belum di bawah git.** Sekarang sudah ada kode nyata (installer, manifest, 5 file instruksi) tanpa jaring pengaman versi. Ini makin mendesak.
