## Jeda data → animasi (target ≤ 5 s)
Perubahan data menjadi event di UI: 3,9 s (run mulai), 4,5 s (pause), 1,3 s (resume): **di bawah 5 s**. Waktu "karakter mulai berjalan" yang teramati 5,3 s dibatasi oleh interval polling skrip ukur (±1 s); dalam kode, jalur sudah ditetapkan saat event diterapkan dan karakter bergerak pada frame berikutnya. Polling bridge dipercepat dari 2 s ke 1,5 s setelah pengukuran; jeda terbesar muncul saat CPU padat (Chromium merekam video bersamaan).

## Temuan dari pemakaian nyata (diperbaiki)
1. **Teleport saat satu poll lambat.** Bridge menandai Paperclip "putus" setelah satu kegagalan, lalu klien membaca ulang snapshot sehingga karakter melompat tanpa berjalan (epoch sempat 7). Kini baru dianggap putus setelah 3 kegagalan beruntun; ada 2 test baru.
2. **Agent berstatus `error`** kini tetap di Pojok Bug selama error belum dibersihkan (sebelumnya hanya 15 menit).
3. Log menutupi Meja Owner dan barisnya mengecil jadi garis: dipindah ke strip bawah.
4. Dua karakter bisa menumpuk di slot Lounge yang sama: slot kini unik (test 3 menit).

## Temuan di luar UI (penting untuk E1.2)
- **Run nyata gagal dengan `setup_failed`** (`Command failed: node -e … host`, stderr kosong), ±24 s setelah mulai, tanpa token terpakai. Skrip setup runner yang sama berjalan normal bila dijalankan manual (exit 0), sehingga dugaan terkuat adalah timeout akibat CPU padat saat Chromium merekam. **Belum terbukti**; harus diperiksa sebelum E1.2 (run LLM nyata). Agent QA sempat berstatus `error` dan dipulihkan lewat `resume`.
- Run agent LLM nyata dengan sukses (tahap "kembali ke Lounge saat run selesai" dari run sungguhan) **belum teramati**, karena hanya satu run yang diizinkan dan run itu gagal. Perilakunya dibuktikan lewat pause/resume nyata, simulasi, dan test.
