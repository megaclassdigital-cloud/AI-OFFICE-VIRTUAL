## Keputusan desain
- Transisi yang diizinkan untuk agent: todo→in_progress, in_progress→in_review|blocked, blocked→in_progress, in_review→in_progress. `done`/`cancelled` ditolak (hak owner, sejalan dengan approval gate).
- Semua galat (aturan kita maupun Paperclip) dikembalikan `ok:false` dengan pesan, bukan HTTP 500.
- Handler memeriksa issue ada di company run (isolasi antar company).

## Bukti perilaku nyata (`docs/evidence/F1.0d/live-call.txt`)
- `post_comment` 5640 karakter / 6720 byte non-ASCII: HTTP 200, 56 ms, komentar tersimpan utuh (panjang 5640).
- `attach_file`: HTTP 200, 73 ms. `done` dari agent: ditolak. `npm test`: 86/86.

## Temuan dari uji nyata (diperbaiki)
1. Key dokumen Paperclip tidak boleh memuat titik (`^[a-z0-9][a-z0-9_-]*$`); regex saya diperbaiki.
2. Paperclip menolak `in_progress` tanpa assignee. Jalur sukses `set_issue_status` hanya diuji di unit test; di live hanya jalur penolakan, karena menugaskan issue uji ke agent akan memicu run berbayar.

## Yang tidak bisa diverifikasi
- Sukses `todo→in_progress` di server nyata (lihat atas); akan terbukti di E1.1 saat run pipeline nyata.
- Agent LLM benar-benar memilih tool plugin ketimbang curl: baru terlihat di E1.1.
- Instruksi 5 agent tidak diubah satu per satu; protokol bersama disisipkan installer otomatis (perlu `install-division` dijalankan ulang untuk menerapkannya ke agent yang ada).
