## Yang tidak bisa diverifikasi dan alasannya

- **AC0.2–AC0.5** (biaya nol, isolasi company, plugin, budget) — di luar cakupan F0.1, dikerjakan di F0.2–F0.5.
- **Dashboard dengan data nyata** — butuh company dan agent, yaitu F0.3.
- **Backup database otomatis** — `/api/health` melaporkan `database_backup_missing`. Ini wajar: interval backup 60 menit dan instance baru berumur beberapa menit. Belum bisa dibuktikan tanpa menunggu satu siklus.
- **Stabilitas jangka panjang / restart** — server dijalankan lewat `paperclipai run` di shell yang harus tetap terbuka. Belum diuji bertahan setelah reboot (lihat risiko).
- **Direktori log kosong** — `logging.mode` adalah `file` dengan `logDir` yang doctor nyatakan writable, tetapi sampai akhir sesi tidak ada satu pun file log yang dibuat di sana; semua log keluar ke stdout. Belum jelas apakah ini normal (ditulis saat rotasi/flush) atau konfigurasi logging tidak berfungsi. Perlu dicek lagi di F0.2 saat ada run agent yang menghasilkan log.

## Risiko atau asumsi baru

1. **Bentrokan port 3100 dengan ERP-KIOS (ditemukan, sudah dimitigasi).** Ini risiko paling serius yang ditemukan. Karena ERP-KIOS mengikat IPv6 dan Paperclip IPv4, keduanya "berhasil" hidup di port yang sama dan doctor tidak mendeteksinya, tetapi CLI Paperclip diam-diam berbicara ke ERP-KIOS. Kalau tidak ketahuan sekarang, F0.2–F0.5 akan mengirim perintah company/agent/issue ke aplikasi kasir owner dan hasilnya membingungkan. Sudah dipindah ke **3177**. Owner perlu tahu bahwa Paperclip sekarang di `http://127.0.0.1:3177`, bukan 3100.
2. **`paperclipai run` tidak punya Windows service.** Doctor menyatakan "Service management is not supported on win32". Jadi server mati begitu shell ditutup atau komputer restart, dan tidak ada auto-start. Untuk operasi harian (dan untuk F2.4 routine terjadwal Senin–Jumat 07.00) ini masalah nyata. Perlu keputusan: Task Scheduler, atau terima start manual. Kandidat ADR.
3. **Prasyarat VC++ Redistributable tidak terdokumentasi di Paperclip.** Instalasi gagal total dengan pesan yang menyesatkan ("The data directory might already exist") padahal penyebabnya runtime kedaluwarsa. Mesin lain yang dipakai nanti akan kena hal yang sama. Sudah dicatat di `docs/versions.md` dan `install-log.md`.
4. **VC++ runtime sistem diupgrade dari 14.23 → 14.51.** Ini pustaka bersama seluruh sistem, jadi menyentuh aplikasi lain milik owner (ERP-KIOS, JARVIS). Upgrade VC++ dirancang Microsoft agar kompatibel mundur dan ini praktik standar prasyarat PostgreSQL, tapi owner perlu tahu bahwa sesuatu di luar folder proyek ikut berubah.
5. **`telemetry.enabled: true` secara default.** Config hasil quickstart mengaktifkan telemetri. Belum diperiksa apa yang dikirim dan ke mana. Karena proyek ini akan memproses konten dan nantinya API key, owner sebaiknya memutuskan sadar apakah ini dibiarkan. Belum diubah karena di luar cakupan F0.1.
6. **Peringatan izin file kunci rahasia.** Doctor: `master.key` permissions 666, sarannya `chmod 600` — saran khas Unix yang tidak berlaku di Windows. Belum ditindaklanjuti; perlu padanan ACL Windows (`icacls`) di fase keamanan.
7. **Instalasi lewat `npx` bersifat sementara.** CLI sendiri memperingatkan: "This npx run is temporary. Use `paperclipai install` for atomic updates, rollback, and service support." Saat ini biner tinggal di cache npx dan bisa hilang kalau cache dibersihkan. Untuk stabilitas versi (aturan 9) sebaiknya pindah ke `paperclipai install` dengan versi dipin — kandidat tugas tersendiri.
8. **Mesin owner lemah untuk beban ini.** i3-7020U 2 core. Satu `initdb` plus 282 migrasi memakan beberapa menit. Render Playwright (F0.7) dan run agent (F0.2) kemungkinan lambat. Perlu diingat saat menilai KPI waktu.

## Deviasi dari PRD

PRD menulis perintah `npx paperclipai onboard --yes`. Yang dijalankan:

```
npx --yes paperclipai@2026.1001.0 onboard --yes --no-install-service
```

Dua perbedaan, keduanya disengaja:

1. **Versi dipin** (`@2026.1001.0`) — aturan 9 mewajibkan pin versi. Tanpa ini setiap run bisa ikut rilis baru diam-diam.
2. **`--no-install-service`** — memasang Windows service permanen adalah perubahan sistem yang belum diminta owner. Ternyata tidak berpengaruh: doctor melaporkan service memang tidak didukung di win32.
