# F0.4 — AC0.4 Plugin menambah tool tanpa mengubah core

## Yang dibangun

`plugins/aao-approval-gate/` — versi "hello" sesuai PRD:

| Berkas | Isi |
| --- | --- |
| `package.json` | `paperclipPlugin.manifest` menunjuk ke `manifest.js`; dependensi `@paperclipai/plugin-sdk` |
| `manifest.js` | Manifest v1: id, apiVersion 1, categories, capabilities, entrypoints, deklarasi tool |
| `src/plugin.js` | `definePlugin` + registrasi tool `aao_hello`. Tidak memulai RPC, jadi aman di-import test |
| `src/worker.js` | Bootstrap tipis: `startWorkerRpcHost({ plugin })` |

Tool `aao_hello` sengaja deterministik dan tanpa efek samping: memantulkan teks, panjangnya, dan waktu server.

## Empat kebuntuan yang harus dipecahkan

Dokumentasi tidak cukup, jadi skema dibaca langsung dari kode yang terpasang (CLAUDE.md aturan 3).

1. **`plugin init` tidak bisa dipakai.** Gagal: `Package package.json not found at ...\_npx\packages\shared\package.json`. Scaffolder mengharapkan layout monorepo yang tidak ada pada instalasi lewat npx. `plugin examples` juga kosong.

2. **Manifest bukan JSON, melainkan modul JS.** Percobaan dengan `manifest.json` ditolak: `does not appear to be a Paperclip plugin (no manifest found)`. Sumber kebenaran: `@paperclipai/server/dist/services/plugin-loader.js` → `resolveManifestPath()` membaca `pkgJson["paperclipPlugin"].manifest`, dan `loadManifestFromPath()` memakai `await import()` lalu mengambil `mod.default`.

3. **Skema manifest ketat.** Validator `pluginManifestV1Schema` di `@paperclipai/shared/dist/validators/plugin.js` mewajibkan `id`, `apiVersion: 1`, `version` semver, `displayName`, `description`, `author`, `categories` (array, dari `PLUGIN_CATEGORIES`), `capabilities` (array, min 1), `entrypoints.worker`. Aturan silang: mendeklarasikan `tools` mewajibkan capability `agent.tools.register`.

4. **`runWorker()` gagal mendeteksi entrypoint di Windows.** Gejalanya menyesatkan:
   ```
   Worker initialize failed: RPC call "initialize" timed out after 15000ms
   worker process stopped (signal SIGKILL)
   ```
   Tanpa satu baris stderr pun. Penyebabnya `isWorkerEntrypoint()` membandingkan `realpath(import.meta.url)` dengan `realpath(process.argv[1])`; perbandingan itu gagal di sini, sehingga RPC tidak pernah dimulai dan worker hidup tapi diam sampai dibunuh.

   Solusi: pola bootstrap yang disebut README SDK — panggil `startWorkerRpcHost({ plugin })` langsung, tanpa cek main-module. Setelah itu instalasi langsung `ready`.

# F0.5 — AC0.5 Budget habis membuat agent berhenti

## Masalah mendasar yang ditemukan lebih dulu

Run nyata kita berbiaya **nol**: `billingType: subscription_included`, `costStatus: unpriced`, `apiRunCount: 0`. Metrik budget adalah `billed_cents`. Artinya **pemakaian nyata tidak akan pernah memicu budget**, berapa pun banyaknya run.

Jadi menguji dengan "jalankan agent sampai budget habis" mustahil di konfigurasi sekarang. Yang diuji adalah mekanismenya, dengan biaya disuntikkan lewat API resmi `POST /api/companies/{id}/cost-events`.

## Cara uji

1. Pasang budget policy pada agent Researcher: `metric=billed_cents`, `amount=1` (1 sen), `hardStopEnabled=true`.
2. Rekam satu cost event `metered_api` sebesar 250 sen.
3. Periksa status agent.

## Pembersihan setelah uji

Policy dilonggarkan, budget agent dikembalikan ke 0, agent di-`resume`. Status akhir: **`idle`**, policy `status=ok`, `paused=false`.

**Yang TIDAK bisa dibersihkan:** cost event 250 sen sintetis itu tetap ada di ledger. `costs/summary` sekarang menunjukkan `spendCents: 250` padahal pemakaian sebenarnya USD 0. Angka ini **harus diabaikan** saat membaca KPI biaya, atau database di-reset sebelum produksi. Ini konsekuensi dari menguji budget tanpa membakar uang sungguhan.

## Risiko atau asumsi baru

1. **Budget guard tidak akan pernah menyala dengan adapter langganan.** Ini yang paling penting. KPI PRD "biaya ≤ USD 5/bulan" dan mitigasi "budget alert" tidak berfungsi selama `codex_local` dipakai, karena biayanya tercatat 0. Yang membatasi pemakaian hanyalah rate limit langganan Codex owner, yang tidak terlihat oleh Paperclip. Kalau perlindungan biaya nyata dibutuhkan, batasnya harus pada hal lain (jumlah run, durasi, token), bukan `billed_cents`.

2. **Ledger biaya tercemar data uji** sebesar 250 sen (lihat di atas).

3. **`runWorker()` dari SDK resmi tidak bisa dipakai di Windows ini.** Semua plugin kita harus memakai pola bootstrap `startWorkerRpcHost`. Kalau upstream mengubah perilaku ini, plugin kita perlu diuji ulang. Sudah ditulis sebagai komentar di `src/worker.js`.

4. **Plugin berjalan sebagai kode tepercaya.** README SDK menyatakan: "Plugin workers and plugin UI should both be treated as trusted code today" dan UI plugin berjalan same-origin sehingga capability bukan sandbox frontend. Jadi capability di manifest adalah deklarasi, bukan jaminan keamanan. Relevan untuk gate approval di Fase 2.

5. **Project pertama dibuat sebagai efek samping.** `tools/execute` mewajibkan `runContext.projectId` yang nyata, jadi project `Carousel Berita AI` dibuat. Itu wajar untuk pipeline nanti, tetapi perlu dicatat karena lahir dari kebutuhan uji, bukan desain.

## Yang tidak bisa diverifikasi dan alasannya

- **Agent memanggil tool plugin lewat LLM.** Tool terbukti terdaftar dan bisa dieksekusi lewat API, tetapi belum diuji bahwa agent Codex benar-benar memilih dan memanggilnya di tengah run. Itu baru relevan di F1.3 ketika Verifier memakai tool verifikasi sungguhan.
- **Budget pause menghentikan run yang sedang berjalan.** Yang terbukti baru status agent berubah menjadi `paused` saat agent sedang `idle`. Perilaku saat run sedang aktif belum diuji.
- **Isolasi lewat UI board.** Yang diuji adalah API dengan agent key. Akses board/owner memang lintas company secara desain, jadi tidak diuji sebagai pelanggaran.
