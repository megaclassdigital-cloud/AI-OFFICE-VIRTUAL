### Uji tambahan: determinisme antar proses

Dua render di atas terjadi dalam satu proses browser. Yang lebih penting untuk AC1.5 adalah apakah hasilnya tetap sama setelah Chromium dimatikan dan dijalankan ulang. Script dijalankan dua kali sebagai proses Node terpisah:

```
=== render run #1 (proses baru) ===
sha256Render1: f024f2512cf690b4d637d90d584aafcf4c7fdc82597227291642ec9111a6bf0d

=== render run #2 (proses terpisah, browser di-launch ulang) ===
sha256Render1: f024f2512cf690b4d637d90d584aafcf4c7fdc82597227291642ec9111a6bf0d

hash proses 1: F024F2512CF690B4D637D90D584AAFCF4C7FDC82597227291642EC9111A6BF0D
hash proses 2: F024F2512CF690B4D637D90D584AAFCF4C7FDC82597227291642EC9111A6BF0D
HASIL: IDENTIK antar proses — determinisme bertahan setelah browser restart
```

Jadi hash PNG stabil melintasi restart browser dan restart proses Node. Ini menghapus sebagian besar kekhawatiran terhadap ADR-0002.

| Klaim | Bukti | Angka |
| --- | --- | --- |
| Render PNG 1080×1350 berjalan di Windows | Header PNG hasil | 1080×1350, 523 KB |
| Input sama → berkas identik (prasyarat AC1.5) | SHA-256 dua render | `f024f251…` keduanya |
| Waktu render terukur | Stopwatch di sekitar `page.screenshot()` | 599 ms dan 550 ms |
| Ukuran instalasi tercatat | Folder `%LOCALAPPDATA%\ms-playwright` | **550,1 MB** |

## Masalah yang ditemukan

**`npx playwright install chromium` tidak cukup.** Playwright 1.56 memakai varian `chromium_headless_shell` terpisah untuk mode headless. Setelah hanya memasang `chromium`, run gagal:

```
browserType.launch: Executable doesn't exist at
C:\Users\Farrel\AppData\Local\ms-playwright\chromium_headless_shell-1194\chrome-win\headless_shell.exe
```

Perlu `npx playwright install chromium-headless-shell` juga. Totalnya 550,1 MB (chromium + headless shell + ffmpeg + winldd), bukan ~170 MB seperti perkiraan awal.

## Yang tidak bisa diverifikasi dan alasannya

- **Determinisme lintas mesin dan lintas versi Chromium.** Determinisme antar proses **sudah diuji dan lolos** (lihat di bawah), tetapi belum diuji di mesin lain atau setelah Chromium di-upgrade. Untuk AC1.5 (approval terikat hash PNG) perbedaan sekecil apa pun akan membatalkan approval.
- **Font lokal.** Template uji memakai font sistem ("Segoe UI"). Brand kit dengan font lokal baru dibuat di F1.6. Font sistem berbeda antar mesin, jadi determinisme lintas mesin justru akan bergantung pada font lokal yang dipaketkan.
- **Cek visual otomatis** (overflow dari DOM, kontras ≥ 4,5:1, font minimum) belum dibangun. Itu cakupan F1.8.
- **Contact sheet** dan render banyak slide belum diuji; F0.7 hanya meminta satu slide.

## Risiko atau asumsi baru

1. **Determinisme belum terbukti untuk kasus yang sebenarnya penting.** Approval mengikat hash PNG (F2.2). Kalau Chromium menghasilkan byte berbeda setelah restart atau upgrade, setiap approval akan batal sendiri. Ini risiko langsung terhadap ADR-0002 dan harus diuji sebagai hal pertama di F1.8.

2. **Upgrade Chromium berbahaya.** Versi browser harus dipin dan diperlakukan seperti dependency produksi, karena perubahan rendering sekecil apa pun mengubah hash.

3. **550 MB untuk satu fitur.** Besar, tetapi sepadan: ini satu-satunya cara memenuhi ADR-0002 (render deterministik dari template HTML/CSS). Alternatif cadangan Satori + resvg tercatat di ADR-0002 bila Chromium bermasalah.
